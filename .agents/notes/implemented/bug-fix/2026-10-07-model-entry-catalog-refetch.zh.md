# Agent Note: 打开模型入口时重新拉取模型目录

Status: implemented

[English](2026-10-07-model-entry-catalog-refetch.md) | 中文

## 问题

`ModelCatalogDirectory` 每个 Host 代次只加载一份目录，只有在转发的 `llm/adapters-updated`、`settings/document-updated` 与凭据事件上或连接重置时才重新拉取。提供方的模型列表在这些事件之外也会变化：opencode2dsh 适配器每五分钟重拉一次 Zen 列表，而 Host 的 `session/modelCatalog` 每次调用都据此重建，因此 Host 侧的答案始终是最新的，浏览器却保留首次响应。两个入口都经 `load()` 读取，它直接返回已就绪的缓存，所以提供方新增的模型只有在重载或无关的设置改动之后才会出现在选择器里。

## 决策

打开任一入口都会重新拉取。`/model` 的选项构建器与 composer 位的 `load` 回调都改为调用 `ModelDirectory.reload()`，它委托给 `ModelCatalogDirectory.reload()`：丢弃缓存结果并加载，若已有加载在运行则加入其中，使同时打开的多次读取共享同一个请求。打开时的拉取失败会保留最近一次加载的分组，并把错误留在 store 上——弹层继续列出这些行，composer 位显示行内错误——只有在从未成功加载过目录时才抛出，此时弹层外壳的错误与重试本就无内容可渲染。`load()` 还把超过 `CATALOG_FRESH_MS`（五分钟）的值视为过期并重新拉取，使打开路径之外的读取自行老化。转发事件驱动的刷新路径保持不变。

## 备选方案

**Host 主动推送事件。** 让 opencode2dsh 适配器的 `onRefresh` 发出一个新的转发事件，两个入口订阅它。它能在无用户交互时更新列表，但要跨越 profile-web 补丁、远程事件表、转发文档以及两套 SDK 投影，才服务于一个选择器；而且在首次刷新之前仍需打开路径作为兜底。推迟到出现第二个需要推送更新的消费方时再做。

**客户端定时轮询。** 客户端周期性重拉会刷新没人正在看的列表，且与包 README 记录的事件驱动设计相矛盾。`load()` 中的新鲜度上限在不引入定时器的情况下限制了陈旧程度。

**仅设新鲜度上限。** 五分钟的上限仍会让用户打开入口挑选的那一刻看到最多五分钟前的列表，而那正是本次改动要解决的问题。

## 后果

每次 `/model` 或 composer 位打开都会产生一次目录 RPC，并发打开经单飞加载共享它。目录加载过一次之后的拉取失败会让两个入口退回到保留的分组，而不是弹层的错误外壳，因此 Host 的瞬时故障不再把选择器清空。该上限是模块常量而非 cordis.yml 字段：浏览器半侧没有配置面，且它限制的是展示新鲜度，不是部署选择。

## 测试

`tests/catalog.client.spec.ts` 用伪造时钟钉住新鲜度上限（上限内返回缓存、超过则重拉）与重拉的单飞合并。`tests/browser-plugin.client.spec.ts` 钉住两个入口在没有 Host 事件时的打开即重拉、拉取失败时保留的分组与 store 错误，以及从未加载过时的抛出。
